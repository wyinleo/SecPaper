### 1. NanoTag: Systems Support for Efficient Byte-Granular Overflow Detection on ARM MTE

- **方向**：系统与硬件安全 / 内存安全
- **关键词**：ARM MTE、缓冲区溢出、概率检测、异常处理
- **名词解释**：
  - **内存标记扩展（MTE）**：ARM 为指针和 16 字节内存块附加短标签，访问时比较标签；同一块内部的越界仍可能漏过。
  - **绊线标签**：NanoTag 随机把短分配对象所在块标成会触发异常的标签，再由软件判断访问是否真的越过对象边界。
- **单位与作者**：Columbia University：Mingkai Li、Hang Ye、Suman Jana、Tanvir Ahmed Khan；University of Pennsylvania：Joseph Devietti
- **出处与状态**：IEEE S&P 2026｜接收
- **公开或更新时间**：2025-09 预印版本；2026-05 正式发表
- **原文链接**：[DOI](https://doi.org/10.1109/SP63933.2026.00231)；[arXiv](https://arxiv.org/abs/2509.22027)
- **核心问题**：ARM MTE 以 16 字节为一个标记粒度，无法发现对象末尾仍落在同一粒度内的越界。论文研究能否在现有硬件上补齐字节级边界，同时把运行开销控制在接近原生 MTE 的水平。
- **方法与贡献**：NanoTag 对短粒度对象按访问频率和分配频率采样，把部分标签设为绊线。访问触发 MTE 异常后，处理器进入软件处理器，恢复隐藏的真实标签、计算字节偏移并检查有效范围；合法访问被临时放行并重放，随后重新安装绊线。
- **方法示例**：一个对象只占 16 字节块中的前 8 字节，程序向第 10 字节写入。普通 MTE 看到指针与整块标签一致，NanoTag 的绊线先触发异常，软件再发现偏移超过 8 字节并报告越界。
- **实验与证据**：Juliet 测试中，NanoTag 检出 97.57% 的堆缓冲区溢出，ASan 为 98.66%，同步 MTE 为 75.68%；SPEC CPU2017 平均运行开销 12.50%，ASan 为 95.11%，同步 MTE 为 11.98%。Magma 模糊测试吞吐损失 15.86%，明显低于 ASan 的 111.20%。
- **局限与风险**：概率采样会留下漏检窗口，标签碰撞也可能绕过检查；部分异常重放受处理器调试机制限制。评估集中在 Pixel 8 与 Android 15，微架构侧信道和其他 ARM 实现仍需单独验证。
- **实践关系**：移动与嵌入式系统可在高风险进程提高采样率，在性能敏感进程降低采样率；部署前需要把异常处理、信号行为和调试机制纳入兼容性测试。
- **推荐理由**：论文把现有硬件的粗粒度保护扩展到对象内边界，并用真实 CVE、基准程序和模糊测试同时衡量安全覆盖与成本。

### 2. Finding SSH Strict Key Exchange Violations by State Learning

- **方向**：网络与通信安全 / SSH 协议测试
- **关键词**：SSH、严格密钥交换、状态机学习、认证前攻击
- **名词解释**：
  - **严格密钥交换**：SSH 的扩展规则，要求握手阶段拒绝不应出现的消息，防止攻击者借消息插入扰乱会话状态。
  - **状态机学习**：把实现当作黑盒反复发送消息，根据响应推断它在什么状态、接受哪些转换。
- **单位与作者**：Ruhr University Bochum：Fabian Bäumer、Marcel Maehren、Marcus Brinkmann、Jörg Schwenk
- **出处与状态**：ACM CCS 2025｜接收
- **公开或更新时间**：2025-09 预印版本；2025-10-13 正式发表
- **原文链接**：[DOI](https://doi.org/10.1145/3719027.3765208)；[arXiv](https://arxiv.org/abs/2509.10895)
- **核心问题**：SSH 严格密钥交换依赖实现正确拒绝握手中的意外消息，手工审查很难覆盖消息顺序和算法组合。论文用自动状态学习寻找实现与规范之间的偏差。
- **方法与贡献**：作者扩展 LearnLib/TTT 黑盒学习器，设计能生成有效与无效 SSH 消息的映射层，并用正常握手变异构造查询；对十个实现和最多五种密钥交换算法学习 33 个状态机，再按消息阶段检查违反严格规则的转换。
- **方法示例**：在密钥协商尚未结束时插入 `CHANNEL_OPEN` 与执行请求。合规实现应立即断开；Erlang SSH 会把请求留到密钥建立后执行，导致认证前命令执行。
- **实验与证据**：十个实现中七个存在严格密钥交换违规。研究发现 Tectia SSH 的会话劫持条件，以及 Erlang SSH 的未认证远程代码执行 CVE-2025-32433，CVSS 评分 10.0；缺陷分为交换前消息、流程相关、阶段无关和过早解除限制四类。
- **局限与风险**：学习结果依赖映射层对实现响应的抽象，网络时序和随机性可能造成不稳定；论文用多次投票降低噪声。范围集中于握手和严格密钥交换，未系统覆盖认证后的全部协议状态。
- **实践关系**：协议实现团队可以把学习到的反例转成回归测试，并让 CI 对多种算法组合重复检查；关键断言应明确绑定当前阶段，避免只在部分消息路径执行。
- **推荐理由**：它把协议文字中的顺序约束转成可运行黑盒测试，并从状态偏差追到两个高影响真实漏洞。

### 3. Vault Raider: Stealthy UI-based Attacks Against Password Managers in Desktop Environments

- **方向**：身份与隐私 / 桌面密码管理器
- **关键词**：密码管理器、桌面自动填充、合成输入、界面欺骗
- **名词解释**：
  - **通用自动填充**：密码管理器在浏览器之外向原生桌面应用填写账号、密码或一次性验证码。
  - **合成键盘输入**：程序通过操作系统接口模拟按键；攻击应用可借此驱动密码管理器的快捷入口。
- **单位与作者**：University of Illinois Chicago：Andrea Infantino、Mir Masood Ali、Kostas Solomos、Jason Polakis
- **出处与状态**：NDSS 2026｜接收
- **公开或更新时间**：2026-02-23 正式发表
- **原文链接**：[会议页面](https://www.ndss-symposium.org/ndss-paper/vault-raider-stealthy-ui-based-attacks-against-password-managers-in-desktop-environments/)；[DOI](https://doi.org/10.14722/ndss.2026.231067)
- **核心问题**：浏览器能把自动填充绑定到域名，桌面应用缺少同等稳定的身份和输入边界。论文系统检查五款密码管理器在 macOS、Windows 和 Linux 上如何识别请求者、接收输入与选择填充目标。
- **方法与贡献**：作者组合应用身份伪装、Bundle ID 复用、合成按键、隐藏字段、窗口叠放与屏外移动，测试 1Password、Keeper、LastPass、KeePassXC 和 MacPass 的 Quick Access/AutoType 路径，并提出绑定进程身份、拒绝合成输入和限制窗口位置等缓解措施。
- **方法示例**：恶意应用伪装成常用程序并把登录框移到屏外，再模拟快捷键唤起密码管理器。用户看到的前台窗口没有变化，凭据却被自动输入到攻击者控制的字段。
- **实验与证据**：攻击可窃取账号、密码、一次性验证码、信用卡信息，部分路径还能取得系统密码、主密码或 Secret Key。macOS 上一组账号密码约需 4—17 秒；1Password 的一次性验证码路径总计约 15 秒，仍在 30 秒有效期内。五家厂商均确认问题，部分已着手修复，Keeper 提供漏洞赏金。
- **局限与风险**：攻击要求本地恶意应用存在且密码库已解锁；macOS 路径通常需要用户授予 Accessibility 权限。测试固定在论文列出的版本，Linux 上部分动作较难隐藏，通行密钥和系统钥匙串不在直接评估范围。
- **实践关系**：桌面密码管理器应把“哪个进程请求、输入是否合成、字段是否可见”联合校验；企业也应审计拥有辅助功能权限的应用，避免把该权限视为普通可用性设置。
- **推荐理由**：论文把跨操作系统 API 差异、产品设计和可复现窃取链路连在一起，清楚说明桌面自动填充为何需要独立威胁模型。

### 4. Patcher: Post-Hoc Patching of Backdoored Large Language Models

- **方向**：人工智能安全 / 模型后门修复
- **关键词**：大模型后门、触发词定位、事后修复、安全对齐
- **名词解释**：
  - **响应条件梯度显著性**：根据某个危险回答反向计算输入词元对该回答的影响，用来定位可疑触发片段。
  - **KL 约束**：限制修复后模型在正常输入上的输出分布偏离原模型，减少安全修复造成的能力损失。
- **单位与作者**：University of Louisville：Anjun Gao、Yufei Xia、Minghong Fang；University of North Texas：Yueyang Quan、Zhuqing Liu
- **出处与状态**：USENIX Security 2026｜接收
- **公开或更新时间**：2026-08-12 正式发表
- **原文链接**：[会议页面](https://www.usenix.org/conference/usenixsecurity26/presentation/gao-anjun)
- **核心问题**：部署方可能只收到一条越过安全限制的报告，无法判断它来自自然对齐缺陷还是训练数据后门，也不知道攻击者的投毒样本。论文研究能否用这一条失败案例修复模型。
- **方法与贡献**：Patcher 先按危险响应计算逐词梯度显著性，再用自适应聚类分离触发词与正常上下文；随后合成带触发和不带触发的有害请求，用拒答损失打断关联，同时用 KL 项锚定正常任务与普通越狱请求的行为。
- **方法示例**：模型遇到一句含隐藏触发词的危险请求时给出操作步骤。系统从该回答反推哪些词元异常影响生成，生成同类触发请求训练模型拒答，同时让无触发的正常问答保持原输出。
- **实验与证据**：在 Llama、Qwen、Falcon 和五类后门上，Patcher 通常把攻击成功率降到接近 0，并把正常任务准确率维持在约 0.92—0.94；自适应攻击下成功率仍约 0.01—0.02。Qwen2.5-32B 上修复耗时约 1,369 秒，触发定位精确率 0.84—0.88、召回率 0.93—0.96。
- **局限与风险**：方法假设攻击者只能污染微调数据，部署方拥有模型参数和一小组干净验证数据；软提示、参数直接篡改和训练流程被控不在范围。拒答质量由模型裁判评估，缺少人类复核。
- **实践关系**：模型供应链事件响应可把单条报告作为调查入口，但仍需保存原模型、验证集和训练来源证据；修复后的正常能力、普通越狱鲁棒性与触发变体应分开回归。
- **推荐理由**：论文面向“只知道一次失败”的现实条件，把触发定位、修复与能力保持放进同一流程，也测试了攻击者适应防御后的表现。

### 5. Analyzing Bytes: Pre-Disassembly Static Binary Analysis

- **方向**：软件与应用安全 / 静态二进制分析
- **关键词**：二进制分析、反汇编、超集控制流图、函数识别
- **名词解释**：
  - **穷举反汇编**：把二进制每个字节偏移都当作潜在指令起点，保证包含真实指令，也会产生大量重叠的伪指令。
  - **超集控制流图**：把这些候选指令和跳转关系放进同一张图，真实与非真实路径同时存在。
- **单位与作者**：Google：Huan Nguyen；Stony Brook University：Soumyakant Priyadarshan、Chencheng Jiang、R. Sekar
- **出处与状态**：ACM PLDI 2026｜接收
- **公开或更新时间**：2026-06-08 正式发表
- **原文链接**：[DOI](https://doi.org/10.1145/3808292)；[会议页面](https://pldi26.sigplan.org/details/pldi-2026-papers/49/Analyzing-Bytes-Pre-Disassembly-Static-Binary-Analysis)
- **核心问题**：复杂 x86 二进制要靠静态分析提高反汇编准确率，静态分析本身又依赖先得到可信指令和函数，形成循环依赖。论文研究能否在决定反汇编结果之前直接分析原始字节。
- **方法与贡献**：Amace 在每个偏移解码指令并建立超集 CFG，利用反向分析的性质，让非真实路径不会污染真实指令处的结论；它同时计算栈深、寄存器保持、非返回调用和无效指针访问，并在一次线性处理中为每个偏移产生结果。
- **方法示例**：同一串 x86 字节可从不同位置解码成重叠指令。Amace 从返回点反向传播约束；真实函数入口会得到一致的零栈深与被调用者保存寄存器信息，伪入口缺少这种组合证据。
- **实验与证据**：函数入口和非返回调用识别的 F1 分别为 94% 与 73%，与先进工具相当。全部偏移分析总耗时约 248 分钟，Angr 为 588 分钟、Ghidra 为 1,615 分钟；作者报告算法随二进制大小线性扩展，并公开了可复现实物。
- **局限与风险**：方法集中于 x86、非重叠正常代码和适合反向表达的分析；间接控制流、异常处理及混淆代码会削弱超集图质量。内存消耗高于部分传统工具，跨架构效果尚未验证。
- **实践关系**：逆向与漏洞分析工具可把 Amace 结果作为反汇编前的证据层，再交给后续函数恢复或规则分析；对含嵌入数据的二进制尤其适合减少错误起点。
- **推荐理由**：论文绕开“先反汇编还是先分析”的循环依赖，并给出准确率、复杂度和真实工具运行成本三类证据。

### 6. Security Reasoning via Substructural Dependency Tracking

- **方向**：软件与应用安全 / 类型系统与安全证明
- **关键词**：子结构类型、能力安全、信息流、协议顺序
- **名词解释**：
  - **子结构类型**：通过限制一个值能否丢弃、复制或交换顺序，把资源使用规则编码进类型。
  - **输出依赖跟踪**：约束结果在产生时必须说明依赖过哪些资源，使系统能检查能力、次数和操作顺序。
- **单位与作者**：Carnegie Mellon University：Hemant Gouni、Frank Pfenning、Jonathan Aldrich
- **出处与状态**：ACM POPL 2026｜接收，Distinguished Paper
- **公开或更新时间**：2026-01-15 正式发表
- **原文链接**：[DOI](https://doi.org/10.1145/3776669)；[会议页面](https://popl26.sigplan.org/details/POPL-2026-popl-research-papers/29/Security-Reasoning-via-Substructural-Dependency-Tracking)
- **核心问题**：能力、泄漏次数、沙箱降权和认证顺序通常由不同机制表达。论文寻找一套统一类型结构，让程序输出携带“曾用过什么、用了几次、按什么顺序”的证明。
- **方法与贡献**：Qrtt 用多个子结构模式控制弱化、收缩和交换，从输出端追踪严格、仿射、线性与有序依赖；同一演算可表达不可伪造能力、定量信息流、类似 `seccomp` 的降权阶段和认证协议，并用逻辑关系一次证明能力、数量与协议安全。
- **方法示例**：服务类型规定高权限操作只能发生在 `auth` 之后，`drop` 之后只能调用低权限操作。若程序先降权再调用高权限接口，输出依赖顺序无法满足类型，检查器在编译期拒绝该路径。
- **实验与证据**：论文给出能力、定量泄漏、沙箱和认证协议的形式化编码与统一基本定理，证明良类型程序满足相应安全性质；这是一项理论工作，没有运行时基准或大规模程序评估。
- **局限与风险**：当前核心语言缺少递归类型和完整算法化类型推断，复杂依赖会增加注解负担；定量泄漏按资源使用计数，无法直接替代熵或差分隐私度量。工程可用性仍需实现和用户研究。
- **实践关系**：安全 API 设计者可把“一次性令牌”“认证后才能读取”“降权后不可恢复”编码为类型接口，减少散落在代码中的动态检查；落地前需要更好的推断和错误信息。
- **推荐理由**：它用一个统一形式系统解释多类看似分散的安全机制，也清楚展示输出端资源推理怎样抓住操作顺序错误。

### 7. Acumen: A Platform for Encrypted and Accountable Collaborative Editing

- **方向**：系统与硬件安全 / 加密协作系统
- **关键词**：端到端加密、协同编辑、CRDT、可验证快照
- **名词解释**：
  - **CRDT**：多个副本可并发修改、稍后自动合并的数据结构，不依赖中心服务器决定唯一顺序。
  - **分叉因果一致性**：恶意中继若向不同用户展示不同历史，之后无法悄悄把分叉重新合并而不被发现。
- **单位与作者**：Stanford University：Ryan Cottone；University of California, Berkeley：Darya Kaviani、Conor Power、Will Giorza、Evelyn Koo、Natacha Crooks、Raluca Ada Popa
- **出处与状态**：USENIX OSDI 2026｜接收
- **公开或更新时间**：2026-07-13 正式发表
- **原文链接**：[会议页面](https://www.usenix.org/conference/osdi26/presentation/cottone)
- **核心问题**：端到端加密让服务器无法代替客户端合并和验证编辑；新成员加入时还需要可信快照，且不应看到加入前的编辑历史。论文研究怎样同时满足实时协作、恶意中继防护和历史隐私。
- **方法与贡献**：Acumen 在 Treedoc CRDT 上为每个用户维护历史哈希与版本向量，用常数空间的签名 Merkle 累加器承诺文档结构和操作集合；新成员验证强一致快照，二阶异步安全垃圾回收在各副本确认后删除旧操作。
- **方法示例**：邀请新同事加入文档时，任一现有成员都可生成加密快照。新成员验证累加器和签名，确认快照对应所有已确认编辑，同时只看到当前内容，看不到此前谁在何时改过哪些段落。
- **实验与证据**：Automerge 轨迹含 182,315 次插入和 77,463 次删除；在 850 次编辑时，Acumen 本地操作约 0.29—0.44 毫秒，Snapdoc 为 5.63—193.7 毫秒。完整网络实验中 25 名用户各以 60 WPM 输入时，平均延迟 2.7 毫秒、吞吐 270 ops/s。
- **局限与风险**：Treedoc 在快照前仍会泄漏部分因果访问结构，系统也不处理时序泄漏和拒绝服务；安全性依赖 PKI 与安全群组消息。用户数、长文档和广域高延迟下的规模仍有限。
- **实践关系**：端到端加密协作产品可把快照邀请、历史隐藏和垃圾回收视为一组协议设计问题；上线时仍需独立的成员身份、设备撤销和抗流量分析措施。
- **推荐理由**：论文把密码性质与可交互延迟放在同一系统里评估，并解决了“新成员如何相信当前文档”这一容易被忽略的协作环节。

### 8. Conjunctive Prompt Attacks in Multi-Agent LLM Systems

- **方向**：人工智能安全 / 多智能体提示攻击
- **关键词**：多智能体安全、提示注入、路由优化、组合攻击
- **名词解释**：
  - **合取攻击**：两个条件必须同时满足才触发；本文的用户触发键与远程智能体模板单独看都无害。
  - **Gumbel-Softmax**：把离散路由选择近似成可求梯度的连续选择，让攻击者联合优化触发位置和消息流向。
- **单位与作者**：University of Central Florida：Nokimul Hasan Arif、Qian Lou、Mengxin Zheng
- **出处与状态**：ACL 2026｜接收
- **公开或更新时间**：2026-07 正式发表
- **原文链接**：[ACL Anthology](https://aclanthology.org/2026.acl-long.1577/)；[DOI](https://doi.org/10.18653/v1/2026.acl-long.1577)
- **核心问题**：多智能体系统把提示分段并通过路由发送给不同代理，局部过滤器只检查单条消息。论文研究两个分别无害的片段经路由相遇后，能否形成现有护栏看不到的系统级触发。
- **方法与贡献**：攻击者只控制用户查询中的触发键和一个远程智能体的隐藏模板，不修改权重或客户端；可微优化同时选择触发位置、模板位置与路由偏置，并在星形、链式和 DAG 拓扑上比较干净、仅键、仅模板与两者同时出现四种状态。
- **方法示例**：用户问题里出现一个普通项目代号，远程检索代理的模板里含一条看似正常的条件句。只有路由把问题送到该代理时，两段内容才合并成有害指令，单独扫描任一段都难以报警。
- **实验与证据**：Gemma-2B、Mistral-7B 和 Llama3-8B 的三类拓扑中，基线同时触发的平均攻击成功率约 0.23—0.33，完整优化提高到 0.60—0.65，部分配置达到 1.0；单条件误触发通常接近零。PromptGuard、Llama Guard 和工具限制均未稳定阻断组合路径。
- **局限与风险**：路由器采用可微概率抽象，无法覆盖生产系统的全部调度、缓存与权限逻辑；实验限定一个被控远程代理、三类拓扑和有限模型，尚未测试长对话、多代理串谋与动态工具链。
- **实践关系**：多智能体防线需要记录端到端消息来源、路由和组合后的有效提示，再按任务权限做联合检查；只对单个代理输入输出分类会漏掉跨组件触发。
- **推荐理由**：论文把“每段都通过检查”与“组合后仍安全”明确区分，并用四状态实验验证攻击依赖两个条件同时出现。

### 9. PrivAct: Internalizing Contextual Privacy Preservation via Multi-Agent Preference Training

- **方向**：身份与隐私 / 多智能体上下文隐私
- **关键词**：上下文隐私、偏好训练、多智能体、隐私与效用
- **名词解释**：
  - **上下文完整性**：信息能否分享取决于发送者、接收者、内容和场景关系，同一事实在不同对象之间有不同隐私边界。
  - **泄漏条件非对称奖励**：一旦有泄漏就同时惩罚泄漏和靠泄漏换来的帮助性；完全无泄漏后再奖励回答质量。
- **单位与作者**：Duke University：Yuhan Cheng、Hancheng Ye、Hai Helen Li、Yiran Chen；University of Florida：Jingwei Sun
- **出处与状态**：ICML 2026｜接收
- **公开或更新时间**：2026-07-06 正式发表
- **原文链接**：[PMLR](https://proceedings.mlr.press/v306/cheng26o.html)
- **核心问题**：提示或外部审查代理在推理时处理隐私，容易依赖场景模板，也可能让中间推理暴露更多敏感内容。论文尝试把上下文隐私偏好直接训练进多智能体各组件的生成行为。
- **方法与贡献**：PrivAct 用生成器、验证器、修订器形成树状候选轨迹，把末端隐私与帮助性奖励向上回传，为每个代理构造 DPO 偏好对；泄漏条件非对称奖励避免模型通过透露少量隐私换取高帮助性。
- **方法示例**：教会成员询问社区近况，牧师掌握另一位成员的搬家与家庭情况。基础模型为显得有帮助而复述细节，PrivAct 学会省略该私密信息，同时回答其他公开近况。
- **实验与证据**：在 Mistral-7B 上，AIFC 平均帮助性 86.93%，PrivAct 为 86.30%，但 AIFC 平均泄漏率高 12.32 个百分点（23.7% 对 11.4%）。四个骨干模型均得到更优隐私—帮助性前沿，训练结果还零样本迁移到 ConfAIde，并跨多种代理拓扑保持优势。
- **局限与风险**：隐私和帮助性主要由 LLM 裁判判断，训练集来自 PrivacyLens 的 394 个案例；部署到资源受限设备的计算与内存成本仍高。文化、组织和长期对话中的隐私规范可能超出训练分布。
- **实践关系**：处理邮件、日程或健康信息的代理可把隐私偏好训练与推理时访问控制结合；例如模型学会少说，工具层仍要阻止它读取无权访问的数据。
- **推荐理由**：论文直接优化“无泄漏前提下的帮助性”，也用跨基准和跨拓扑实验检查偏好是否只记住单一工作流。

### 10. AGENTSAFE: Benchmarking the Safety of Embodied Agents on Hazardous Instructions

- **方向**：人工智能安全 / 具身智能体评测
- **关键词**：具身智能体、危险指令、规划安全、多阶段诊断
- **名词解释**：
  - **任务规划拒绝率（PRR）**：模型在规划阶段识别危险并拒绝生成可执行方案的比例。
  - **仿真到现实差距**：在模拟器中成立的感知、碰撞和动作结果，转到真实机器人后可能改变。
- **单位与作者**：北京航空航天大学：Zonghao Ying、Le Wang、Yisong Xiao、Yuqing Ma、Jinyang Guo、Aishan Liu、Xianglong Liu；中关村实验室：Jiakai Wang、Xianglong Liu；The University of Sydney：Zhenfei Yin；河南科技大学：Mingchuan Zhang；Institute of Dataspace：Xianglong Liu
- **出处与状态**：CVPR 2026｜接收
- **公开或更新时间**：2026-06 正式发表
- **原文链接**：[CVF 页面](https://openaccess.thecvf.com/content/CVPR2026/html/Ying_AGENTSAFE_Benchmarking_the_Safety_of_Embodied_Agents_on_Hazardous_Instructions_CVPR_2026_paper.html)
- **核心问题**：具身安全基准常只看最终任务是否完成，无法区分感知、规划与执行哪个阶段放过了危险指令。论文构建可交互沙箱和分阶段诊断，覆盖对人、环境和智能体自身的风险。
- **方法与贡献**：AGENTSAFE 包含把 VLM 高层输出映射到 AI2-THOR 动作的 SAFE-THOR、45 个场景和 1,350 个危险任务组成的 SAFE-VERSE，以及分别度量目标定位、幻觉、规划、拒绝和任务执行的 SAFE-DIAGNOSE；SAFE-AUDIT 在初始规划思路处进行零样本审计和改写。
- **方法示例**：指令要求点燃房间。模型可能准确识别打火机，也能生成连贯步骤，却没有在规划阶段拒绝；分阶段指标会把它记录为感知成功、规划不安全和执行风险。
- **实验与证据**：九个 VLM 与两个工作流上，部分模型对自伤和环境危害的 PRR 接近 0，Step-v1-8k 在两类任务的计划成功率均超过 72%。SAFE-AUDIT 让正常任务平均执行成功率提高 2.22%，危险任务的计划与执行成功率降到平均 3.52% 和 0.48%。
- **局限与风险**：环境基于 AI2-THOR，物理接触、传感噪声和真实设备故障尚未覆盖；攻击以文本越狱为主，作者把更强多模态攻击、学习型审计器和真实环境迁移列为后续工作。
- **实践关系**：机器人和桌面代理评测应把感知、规划、工具调用和动作结果分段记录；规划前审计能降低危险动作进入执行层的概率，但仍需执行层硬约束作为最后防线。
- **推荐理由**：论文用同一任务链定位安全失败发生在哪一层，并展示只看最终成功率会掩盖“已理解危险却仍照做”的关键问题。

- *Finding SSH Strict Key Exchange Violations* 延续协议状态学习路线，并把规范中的“握手阶段不得接受什么”落实为自动反例；它与库内认证前攻击研究共享“边界阶段被提前解除”的风险模式。

- *Security Reasoning* 与 *Acumen* 分别从类型和密码协议把依赖关系显式化：前者追踪资源与顺序，后者追踪编辑历史与快照承诺。
- *Conjunctive Prompt Attacks* 与 2026-W41 的角色混淆研究互补：前者定位跨代理路由组合，后者解释单模型内部为何会误认消息角色。
