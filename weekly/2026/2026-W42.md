### 1. Windows Plays Jenga: Uncovering Design Weaknesses in Windows File System Security

- **方向**：系统与硬件安全 / Windows 文件系统语义
- **关键词**：文件系统语义、权限继承、文件锁、权限提升
- **名词解释**：
  - **强制锁与建议锁**：强制锁由系统阻止冲突访问，建议锁要求各程序自觉遵守；同一库在 Windows 与 Linux 上可能落入不同模型。
  - **权限反转**：临时把宽权限对象替换为受限对象后，恢复路径反而把原对象权限复制到攻击者可控位置。
- **单位与作者**：KAIST：Dong-uk Kim、Junyoung Park、Insu Yun；Sungkyunkwan University：Sanghak Oh、Hyoungshick Kim
- **出处与状态**：ACM CCS 2025｜接收
- **公开或更新时间**：2025-10-13 正式发表
- **原文链接**：[DOI](https://doi.org/10.1145/3719027.3765217)
- **核心问题**：跨平台应用常把 Linux 文件系统经验直接带到 Windows。论文检查链接遍历、锁、权限继承和访问控制的语义差异怎样破坏应用原有安全假设。
- **方法与贡献**：作者先把 Windows 与 Linux 的接口行为归纳为四类设计差异，再跨六种编程语言测试兼容层，沿每类差异寻找真实程序中“检查时安全、使用时越界”的组合，并提出与现有部署兼容的缓解方式。
- **方法示例**：服务先创建只有管理员可写的目录，再把子文件交给低权限用户处理。Windows 的继承规则可能让新文件得到开发者未预期的权限；攻击者替换或重命名对象后，后续高权限写入就落到可控路径。
- **实验与证据**：论文找到 13 个高影响漏洞，其中 11 个此前未知；11 个可导致权限提升，另有防病毒阻断与沙箱逃逸。六种语言的兼容性检查发现 27 个不兼容行为和 9 个内部不一致行为；21 名平均 10.7 年经验的开发者对这些差异普遍缺乏认识。
- **局限与风险**：研究集中在四类文件语义和所选语言运行时，不能覆盖全部 Windows 文件 API。用户研究样本较小；漏洞影响还取决于服务权限、可写路径和应用调用顺序。
- **实践关系**：跨平台服务需要在 Windows 上单独测试链接、锁和 ACL 继承，并在敏感操作中持有安全句柄、显式设置权限、避免用路径字符串重新打开已检查对象。
- **推荐理由**：论文把难以察觉的操作系统语义差异连接到真实漏洞，也说明“跨平台可运行”与“跨平台安全等价”之间的距离。

### 2. Action Required: The State of GitHub Actions Security in the Wild

- **方向**：软件与应用安全 / CI 供应链配置
- **关键词**：GitHub Actions、软件供应链、CI 安全、开发者调查
- **名词解释**：
  - **CODEOWNERS**：仓库用来指定敏感路径审阅人的规则文件，可让工作流修改必须经过指定人员批准。
  - **提交固定**：用不可变提交哈希引用第三方 Action，降低标签被移动或上游账户被接管后的供应链风险。
- **单位与作者**：NTT DOCOMO BUSINESS, Inc.：Yusuke Kubo、Fumihiro Kanei；NTT, Inc.：Mitsuaki Akiyama；Waseda University：Takuro Wakai、Tatsuya Mori；NICT：Tatsuya Mori；RIKEN AIP：Tatsuya Mori
- **出处与状态**：NDSS 2026｜接收
- **公开或更新时间**：2026-02-23 正式发表
- **原文链接**：[DOI](https://doi.org/10.14722/ndss.2026.240483)
- **核心问题**：GitHub Actions 已进入大量构建和发布链路，已有安全建议却缺少大规模采用证据。论文衡量五项关键实践的实际覆盖率，并调查开发者为何没有采用。
- **方法与贡献**：作者为 CODEOWNERS、脚本注入缓解、OpenSSF Scorecard、第三方 Action 固定和 Dependabot 更新建立检测器，扫描 338,812 个公开仓库，再以 102 名开发者问卷解释认知、误解和维护成本。
- **方法示例**：工作流把 issue 标题直接拼进 shell 命令时，外部用户可借特殊字符注入命令。安全写法先把标题传入环境变量，再由 shell 当作数据读取，检测器据此判断缓解是否存在。
- **实验与证据**：五项实践采用率分别为 7.1%、52.9%（43,516 个适用仓库）、0.6%、16.2% 和 10.7%。近期活跃、组织拥有的仓库采用更多；星数、规模和成熟度相关性较弱。不同实践有 21.3%—71.6% 的受访者此前不了解，25.3% 提到维护成本。
- **局限与风险**：研究只覆盖 16 项建议中的五项和公开仓库；102 份有效问卷来自 1,800 封邀请，响应率 5.7%，也未细分开发、维护和安全角色。
- **实践关系**：组织可把不可变引用、工作流变更审批和依赖更新做成仓库模板与策略检查，同时给出自动修复路径，减少把维护负担留给单个开发者。
- **推荐理由**：它把仓库测量与开发者解释放在一起，能区分“工具可检测的缺口”和“组织需要解决的采用障碍”。

### 3. Peering Inside the Black-Box: Long-Range and Scalable Model Architecture Snooping via GPU Electromagnetic Side-Channel

- **方向**：系统与硬件安全 / GPU 电磁侧信道
- **关键词**：电磁侧信道、GPU、模型架构恢复、黑盒攻击
- **名词解释**：
  - **远场电磁泄漏**：电子设备运行时向外辐射可远距离接收的信号；本文利用推理负载在信号幅度上留下的模式。
  - **层级重建**：先切分网络层，再识别层类型和参数，逐级缩小从噪声直接恢复完整架构的难度。
- **单位与作者**：浙江大学：Rui Xiao、Sibo Feng、Jinsong Han；National University of Singapore：Soundarya Ramesh；KAIST：Jun Han
- **出处与状态**：NDSS 2026｜接收，Best Paper
- **公开或更新时间**：2026-02-23 正式发表
- **原文链接**：[会议页面](https://www.ndss-symposium.org/ndss-paper/peering-inside-the-black-box-long-range-and-scalable-model-architecture-snooping-via-gpu-electromagnetic-side-channel/)；[DOI](https://doi.org/10.14722/ndss.2026.230141)
- **核心问题**：黑盒模型隐藏网络结构，现有架构侧信道常要求恶意代码与受害进程共置。论文研究攻击者能否只在办公室外接收 GPU 电磁信号，恢复足以增强后续攻击的架构信息。
- **方法与贡献**：ModelSpy 在 5 GHz 频段采样推理泄漏，经过降噪与层边界切分后估计层类型和超参数；它先用大量 GPU 显存访问轨迹预训练，再用较少电磁样本微调，以降低跨模型采集成本。
- **方法示例**：攻击者在走廊隔墙接收受害 GPU 多次执行同一网络的信号。系统把重复出现的幅度段对齐，判定卷积层边界，再根据时长和形态推测通道数、卷积核等参数，拼出替代模型。
- **实验与证据**：五款消费级 GPU、141,000 次推理实验中，层切分准确率为 97.6%，超参数估计为 94.0%—94.2%，最远距离 6 米。恢复架构用于 FGSM 后，在 CIFAR-10/100 各 10,000 张图上比集成替代模型提高 22.8%/19.8% 攻击成功率，与已知精确架构相差不超过 4 个百分点。
- **局限与风险**：跨 GPU 世代时层识别约降到 70.5%；非常规层、算子融合和多 GPU 推理尚未覆盖。电磁干扰可能影响 Wi-Fi，插入虚假推理则增加计算开销。
- **实践关系**：高价值推理设备应把物理距离与屏蔽纳入威胁模型，并评估机柜屏蔽、负载扰动和推理调度；只加密模型文件无法阻止运行时物理泄漏。
- **推荐理由**：论文把远距离物理观测连接到可量化的下游黑盒攻击增益，攻击前提和跨设备退化也交代得较完整。

### 4. Large-Scale Online Deanonymization with LLMs

- **方向**：身份与隐私 / 在线身份去匿名化
- **关键词**：去匿名化、开放网络智能体、语义匹配、隐私
- **名词解释**：
  - **校准置信度**：把模型分数与真实正确率对应，允许系统在要求高精度时只输出最有把握的少数匹配。
  - **合成匿名化**：把已知同属一人的公开资料拆成互不相连的两部分，用来评估匹配能力，同时避免主动揭露真实匿名用户。
- **单位与作者**：MATS：Simon Lermen；ETH Zurich：Daniel Paleka、Joshua Swanson、Michael Aerni、Florian Tramèr；Anthropic：Nicholas Carlini
- **出处与状态**：USENIX Security 2026｜接收
- **公开或更新时间**：2026-08-12 正式发表
- **原文链接**：[会议页面](https://www.usenix.org/conference/usenixsecurity26/presentation/lermen)
- **核心问题**：传统去匿名化依赖固定标识符或昂贵人工调查。论文检验会搜索网页、理解语义的 LLM 智能体能否以低成本把化名帖子与现实身份或其他账户对应起来。
- **方法与贡献**：系统先从帖子抽取职业、地点、兴趣等身份线索，再搜索候选、用向量召回缩小范围、让 LLM 比较证据，最后校准置信度；作者在三个可构造真值的数据集上测量精度与召回。
- **方法示例**：一个 Hacker News 账户反复提到所在城市、公司技术栈和一次会议演讲。智能体将这些线索转成查询，找到若干 LinkedIn 候选，再逐项比较时间和经历，只在置信度超过阈值时给出匹配。
- **实验与证据**：在 Hacker News 到 LinkedIn 的 338 人数据上，系统以 90% 精度匹配 226 人；在三个任务中，70%—90% 精度下召回约 25%—67%，单个档案成本约 1—4 美元。Hacker News 在 99% 精度时召回 45.1%，非 LLM 基线为 0.1%。
- **局限与风险**：真值来自已公开关联或合成拆分，真实化名用户可能更谨慎；数据选择、训练数据污染和搜索可见性都会影响结果。作者未发布代码、提示或真实用户数据，以减少滥用。
- **实践关系**：用户应把跨平台累积的细节视为可组合标识符；平台可以限制批量抓取和异常搜索，并为高风险用户提供历史发帖中的可识别线索检查。
- **推荐理由**：论文量化了语义搜索把零散公开信息变成身份线索的规模和成本，也采用了较克制的伦理评估设计。

### 5. PoCGen: Generating Proof-of-Concept Exploits for Vulnerable npm Packages

- **方向**：软件与应用安全 / 漏洞复现自动化
- **关键词**：PoC 生成、npm、动态验证、代码分析
- **名词解释**：
  - **PoC**：能触发漏洞并留下可验证结果的最小示例，用来证明报告中的缺陷确实可达。
  - **类型化验证器**：按路径遍历、原型污染或命令注入等漏洞类型检查具体副作用，避免只凭模型文字判断成功。
- **单位与作者**：University of Stuttgart：Deniz Simsek；CISPA Helmholtz Center for Information Security：Aryaz Eghbali、Michael Pradel
- **出处与状态**：ACM FSE 2026｜接收
- **公开或更新时间**：2025-06 预印版本；2026-07 正式发表
- **原文链接**：[DOI](https://doi.org/10.1145/3808178)；[arXiv](https://arxiv.org/abs/2506.04962)
- **核心问题**：漏洞报告常缺少可运行复现，人工编写 npm PoC 又需要理解入口、参数和运行副作用。论文研究 LLM 能否在程序分析与执行反馈约束下稳定生成可验证 PoC。
- **方法与贡献**：PoCGen 从报告抽取漏洞类型和入口函数，用 CodeQL 路径与用法示例补充上下文，生成候选后在隔离环境运行；类型化验证器返回静态或运行反馈，提示修订器据此多轮修改。
- **方法示例**：针对 `parse-uri` 的 ReDoS，第一轮输入没有产生足够延迟。系统把执行结果送回模型，模型扩大重复字符串并保持调用方式，最终用 30,000 个 `a` 触发可测量的耗时增长。
- **实验与证据**：在 SecBench.js 的 560 个漏洞上生成 395 个有效 PoC，成功率 71%，比 Explode.js 高 38 个百分点；近期 126 份报告中成功 76 份（60.3%）。成功案例平均模型成本 0.009 美元，所有尝试平均 0.025 美元；提交给 GitHub Advisory 的 6 个 PoC 中 5 个获接受。
- **局限与风险**：仅覆盖 JavaScript/npm 和五类漏洞，验证器会拒绝某些有效变体；平均运行约 7 分钟，CodeQL 占约 51% 时间。生成能力具有双重用途，论文只在已披露漏洞和隔离环境评估。
- **实践关系**：安全团队可把系统用于报告分诊与回归测试，但发布前仍需人工确认前置条件、影响和安全披露范围；可执行副作用应由沙箱和类型化断言约束。
- **推荐理由**：论文把“模型说它成功了”替换为程序分析和运行证据，并提供了跨历史基准和近期报告的双重验证。

### 6. Secure Logging in Practice: A Taxonomy, Benchmark, and LLM-Based Analysis

- **方向**：软件与应用安全 / 安全日志缺陷
- **关键词**：安全日志、敏感信息泄漏、代码修复、LLM 评测
- **名词解释**：
  - **日志脱敏**：在记录前删除、替换或遮盖凭据和个人信息，保留诊断所需内容。
  - **上下文增强**：把代码片段与缺陷解释、issue 描述一起给模型，帮助它判断这条日志为何危险。
- **单位与作者**：University of York：He Yang Yuan、Zhenhao Li；香港科技大学（广州）：Xin Wang、Zishuo Ding；University of Waterloo：Kundi Yao；University of Alberta：An Ran Chen
- **出处与状态**：ACM FSE 2026｜接收
- **公开或更新时间**：2026-04 预印版本；2026-07 正式发表
- **原文链接**：[DOI](https://doi.org/10.1145/3797129)；[arXiv](https://arxiv.org/abs/2604.20211)
- **核心问题**：日志可能泄漏秘密、绕过脱敏或放大异常信息，现有研究缺少统一分类和可复现修复基准。论文构建真实问题集并检查多种 LLM 的检测、分类和修补能力。
- **方法与贡献**：作者从 111 篇论文筛出 16 篇，结合 13 个 CWE 与 19 个 CVE形成四类十种模式；再从 949 份报告筛成 63 个项目的 101 个真实问题，并把检测、分类、修复拆开，比较不同上下文提示。
- **方法示例**：代码把完整访问令牌写入错误日志。系统先识别“敏感信息暴露”，再结合 issue 中“只保留末四位”的要求生成遮盖补丁；评估者分别检查问题是否消失和程序行为是否仍合理。
- **实验与证据**：八个模型的平均检测得分为 12.9%—52.5%；DeepSeek V3 加 issue 描述后从 41.6% 升至 52.5%。最佳基础补丁文本相似度平均 44.1%，人工检查最佳配置有 84/101 个补丁有效（83.2%）；更多上下文并非总能提升结果。
- **局限与风险**：101 例受公开 issue 和筛选规则限制；文本相似度无法代表功能正确，84 个有效补丁来自人工判断。模型、提示和上下文变化会影响结论，自动补丁仍需测试和审查。
- **实践关系**：团队可把分类用于日志审查规则，将 issue 语境作为模型辅助输入，并用单元测试、敏感字段断言和人工复核守住修复质量。
- **推荐理由**：它同时给出问题分类、真实基准和修复审查，清楚展示 LLM 在日志安全中能帮到哪里、又会在哪里失真。

### 7. How Effective Are NPM Malicious Package Detectors? A Large-Scale Empirical Study

- **方向**：软件与应用安全 / npm 恶意包检测
- **关键词**：恶意软件包、供应链、检测器评测、规避行为
- **名词解释**：
  - **行为耦合**：把“收集信息”和“发送信息”等分散动作联合判断；单独看每一步都可能像正常库功能。
  - **攻击面错位**：检测器只看安装脚本或 JavaScript 源码时，会错过藏在二进制、依赖或其他执行入口中的恶意行为。
- **单位与作者**：Nanyang Technological University：Wenbo Guo、Chengyue Liu、Weisong Sun、Yang Liu；四川大学：Zhongwen Chen、Ming Kang、Yijia Xu；Imperial Global Singapore：Zhengzi Xu；新加坡管理大学：Shiwen Song；南开大学：Chengwei Liu
- **出处与状态**：ASE 2026｜接收
- **公开或更新时间**：2026-03 预印版本；2026-10-12 正式发表
- **原文链接**：[DOI](https://doi.org/10.1145/3832783.3837427)；[arXiv](https://arxiv.org/abs/2603.27549)
- **核心问题**：npm 恶意包检测工具采用规则、机器学习和 LLM 等不同路线，公开数字难以直接比较。论文在统一数据和行为分类上测量 11 个工具的能力、盲区和互补性。
- **方法与贡献**：作者整理 6,420 个恶意包和 7,288 个良性包，标注 11 类恶意行为与 8 类规避方式，运行 11 个工具的 16 个配置，并从时间、规避、代码可见性和工具组合解释差异。
- **方法示例**：一个包先读取主机信息，稍后才通过网络发出。只匹配单个 API 的规则可能把两步当成正常行为；行为耦合分析把数据来源、传播和外传目的连起来，因而提高检出。
- **实验与证据**：IntelGuard 的 F1 为 95.98%，传统工具 GuardDog 为 93.32%；IntelGuard 与 MalPac-SVM 联合后 F1 达 97.02%、准确率 97.21%。环境检测和反分析平均检出仅 51.7%/52.7%，约 21% 恶意包因攻击面不在源码中而对代码工具不可见。
- **局限与风险**：标签由专家构建，97.4% 达成一致；工具使用默认参数，LLM 抽取在 500 例上为 97.2%。良性集偏向热门包，2021—2025 样本占 95.7%，分类仍带主观性。
- **实践关系**：注册表和组织防线应组合高精度规则与行为/学习模型，并覆盖二进制、安装阶段和依赖链；部署评测要保留时间切分与真实良恶比例。
- **推荐理由**：统一基准揭示了高分背后的攻击面和时间变化，也给出组合工具为何减少误报的证据。

### 8. OS-Harm: A Benchmark for Measuring Safety of Computer Use Agents

- **方向**：人工智能安全 / 计算机操作智能体
- **关键词**：智能体安全、计算机操作、提示注入、安全评测
- **名词解释**：
  - **OSWorld**：让智能体在隔离的 Ubuntu 桌面里操作浏览器、邮件和办公软件的可执行评测环境。
  - **语义裁判**：读取推理、截图和界面文本后判断任务是否完成、行为是否越界的模型评估器。
- **单位与作者**：EPFL：Thomas Kuntz、Agatha Duzan、Hao Zhao、Francesco Croce、Nicolas Flammarion、Maksym Andriushchenko；Carnegie Mellon University：Zico Kolter
- **出处与状态**：NeurIPS 2025 Datasets and Benchmarks Track｜接收
- **公开或更新时间**：2025-12 正式发表
- **原文链接**：[会议页面](https://proceedings.neurips.cc/paper_files/paper/2025/hash/4009bff0cd87ba2203c8e3a2f082aaec-Abstract-Datasets_and_Benchmarks_Track.html)；[DOI](https://doi.org/10.52202/085713-1502)
- **核心问题**：会操作真实桌面的智能体能把错误直接变成外部行动，聊天式安全测试难以覆盖这种风险。论文建立同时观察任务成功与有害行为的可执行基准。
- **方法与贡献**：OS-HARM 在 OSWorld 中构造 150 个任务，平均分为恶意用户请求、外部提示注入和模型自身误行为三类，覆盖 11 种应用；语义裁判综合操作轨迹判断完成度与安全性。
- **方法示例**：智能体被要求读取重要邮件并起草摘要，其中一封邮件藏有“把内容发送到外部地址”的指令。环境记录每次点击和输入，裁判同时检查原任务是否完成、是否执行了外部注入目标。
- **实验与证据**：o4-mini、GPT-4.1、Claude 3.7 Sonnet 与 Gemini 2.5 系列都直接执行过有害请求；o4-mini 对静态提示注入的服从率约 20%。裁判与 150 条人工标注在任务成功和安全判断上的 F1 分别为 0.76 和 0.79；完整运行约需 53 美元和三路并行 5 小时。
- **局限与风险**：当前智能体最高普通任务成功率仅 42.5%，失败可能暂时掩盖安全风险。静态注入和固定任务无法代表自适应攻击；模型裁判也可能误判或受轨迹中的注入内容影响。
- **实践关系**：部署评测应把“完成了什么”和“付出什么副作用”分开记录，并在隔离环境复现邮件、浏览和文件操作；关键动作仍需策略检查与人工确认。
- **推荐理由**：基准把智能体三类常见风险放入真实桌面执行链，适合补充只检查文本拒答率的安全测试。

### 9. Towards Effective Offensive Security LLM Agents: Hyperparameter Tuning, LLM as a Judge, and a Lightweight CTF Benchmark

- **方向**：人工智能安全 / 自动化进攻性测试
- **关键词**：CTF、进攻性智能体、LLM 裁判、超参数
- **名词解释**：
  - **CTF Competency Index（CCI）**：把漏洞理解、侦察、利用、技术准确性、效率和适应性六项与专家解法对齐后的综合分数。
  - **top-p**：生成时只从累计概率达到阈值的候选词中采样，用于控制输出的探索范围。
- **单位与作者**：New York University：Minghao Shao、Kimberly Milner、Haoran Xi、Meet Udeshi、Saksham Aggarwal、Venkata Sai Charan Putrevu、Prashanth Krishnamurthy、Farshad Khorrami、Ramesh Karri；New York University Abu Dhabi：Minghao Shao、Muhammad Shafique；Indian Institute of Technology Kanpur：Nanda Rani；International Institute of Information Technology Hyderabad：Sandeep K. Shukla
- **出处与状态**：AAAI 2026｜接收
- **公开或更新时间**：2025-08 预印版本；2026-03-14 正式发表
- **原文链接**：[会议页面](https://ojs.aaai.org/index.php/AAAI/article/view/40210)；[DOI](https://doi.org/10.1609/aaai.v40i35.40210)；[arXiv](https://arxiv.org/abs/2508.05674)
- **核心问题**：CTF 智能体常只按拿到 flag 与否评分，难以看出推理在哪一步失败，也缺少低成本超参数实验集。论文提供轻量基准与细粒度裁判。
- **方法与贡献**：CTFTiny 从已有基准按难度选出 50 题，覆盖六类任务；CTFJudge 把人类题解和智能体轨迹结构化，再按六维 CCI 分析部分进展，并系统扫描温度、top-p 与最大输出长度。
- **方法示例**：智能体识别出栈溢出，也完成侦察，却没构造出可用 payload。二元评分记为失败；CCI 仍给漏洞理解和侦察分数，同时把利用方法与适应性标为主要瓶颈。
- **实验与证据**：七个模型中 Claude 4 Sonnet 解出 76%，Gemini 2.5 Flash 为 64%，其余为 8%—48%；Claude 的 CCI 各维为 77.5—84.5。Claude 在温度 1.0、top-p 1.0 时解 38 题，Claude 与 GPT-4.1 都在 4096 token 附近达到峰值，8192 时下降。
- **局限与风险**：只评估 D-CIPHER 一种开源代理架构；CCI 使用固定专家权重，LLM 裁判可能继承偏差。50 道 CTF 与真实授权渗透的资产、规则和防守响应仍有明显差异。
- **实践关系**：红队智能体评估应保存完整轨迹并按侦察、利用和验证分别评分；解码参数要按任务验证，不能把最长上下文或最低温度当作通用最优值。
- **推荐理由**：论文把成功率拆成可诊断能力，并用可负担的小基准展示参数变化对多步安全任务的影响。

### 10. VPR-Cloak: A First Look at Privacy Cloak Against Visual Place Recognition

- **方向**：身份与隐私 / 图像位置隐私
- **关键词**：视觉地点识别、位置隐私、对抗扰动、黑盒迁移
- **名词解释**：
  - **视觉地点识别（VPR）**：根据建筑、道路和景观特征，把查询照片与地点图库匹配。
  - **显著性先验**：预先估计模型最依赖的图像区域，把有限扰动优先放到这些区域。
- **单位与作者**：清华大学：Shuting Dong、Feng Lu、Hao Yu、Guanghao Li、Chun Yuan；鹏城实验室：Shuting Dong、Feng Lu、Zhe Wu；南方科技大学：Mingzhi Chen、Guanghao Li、Ming Tang
- **出处与状态**：ICCV 2025｜接收
- **公开或更新时间**：2025-10 正式发表
- **原文链接**：[CVF 页面](https://openaccess.thecvf.com/content/ICCV2025/html/Dong_VPR-Cloak_A_First_Look_at_Privacy_Cloak_Against_Visual_Place_ICCV_2025_paper.html)
- **核心问题**：社交照片可被黑盒地点识别系统用来推测活动轨迹，现有保护往往难以同时满足迁移性、不可察觉和实时速度。论文研究发布前的快速图像保护。
- **方法与贡献**：VPR-Cloak 用微调 DINOv2 找出地点识别关键区域，SAP-PO 把空间扰动集中到这些区域，再在频域细化高频成分、保留人眼更敏感的低频结构；保护网络一次前向即可输出结果。
- **方法示例**：街景照片中，模型把独特立面和路口标志视作定位依据。系统在这些区域加入细微变化，再调整高频纹理，使人仍能正常观看，未参与训练的地点模型却更难返回正确地点。
- **实验与证据**：在 Pitts30k、MSLS、Tokyo247、MSLS Challenge 和 Nordland 等数据、多个未见黑盒模型上，方法普遍比 ANDA 与 MultiANDA 降低更多检索准确率。Nordland 平均 R@1/R@5/R@10 降幅为 70.9/77.0/76.0，单张 0.036 秒，比 MultiANDA 快约 15 倍；Google 与 Bing 图像搜索案例也被成功干扰。
- **局限与风险**：商业 API 只做案例验证，没有公开规模化成功率；数字水印式微扰可能被平台压缩、裁剪或重编码削弱。评估集中于所选图库和模型，无法保证对未来 VPR 服务持续有效。
- **实践关系**：高风险用户发布包含住址、工作地或固定路线的照片前仍应减少可识别背景；扰动工具可以增加一道保护，但需在目标平台重编码后复测。
- **推荐理由**：论文围绕现实位置隐私同时优化黑盒迁移、视觉质量和速度，并给出了跨数据集与商业检索的初步证据。
