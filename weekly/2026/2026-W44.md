### 1. Site Isolation is Dead: How Site Isolation is Broken in Agentic Browsers and Extensions

- **方向**：人工智能安全 / 智能体浏览器
- **关键词**：网页智能体、站点隔离、IPC 伪造、信息泄露
- **名词解释**：
  - **站点隔离**：浏览器把不同网站放进不同渲染进程，即使某个页面被攻破，也尽量不让它读取其他站点的数据。
  - **IPC 伪造**：被攻破的渲染进程冒充可信界面，向高权限后台进程发送进程间通信消息。
- **单位与作者**：KAIST：Suyoung Lee、Seongho Keum、Changoo Lee、Dongwon Shin、Sooel Son；Oregon State University：Sanghyun Hong；Seoul National University：Byoungyoung Lee
- **出处与状态**：IEEE S&P 2026｜接收
- **公开或更新时间**：2026-05 正式发表
- **原文链接**：[DOI](https://doi.org/10.1109/SP63933.2026.00241)
- **核心问题**：智能体浏览器为了跨网站执行任务，把模型、存储和页面操作放进高权限后台。论文研究渲染进程已经被漏洞攻破时，传统站点隔离能否继续限制它。
- **方法与贡献**：作者分析 BrowserOS、Nanobrowser 和七款 Chrome 智能体扩展的进程、IPC 与存储路径，构造两类攻击。MPI 冒充任务面板注入提示，让后台智能体代为跨站操作；SLI 借后台暴露的接口读取对话、API 密钥与用户信息。防御要求校验提示来源、按来源限制存储访问，并让额外模型核对每个动作是否符合可信计划、用户请求和已验证历史。
- **方法示例**：攻击者先利用渲染器漏洞控制普通网页，再伪造一条来自任务面板的“打开 HotCRP 并读取投稿”消息。后台把它当作用户指令，登录另一个站点取出内容，随后还能用用户账户发送定向邮件。
- **实验与证据**：作者在 Chromium 130.0.6723.160 上检查两款开源智能体浏览器与七款扩展，所有系统至少暴露一类攻击路径；WebPilot 因动作受限避开 MPI。给 BrowserOS 和 Nanobrowser 加入防护后，100 个 WebArena 任务上的 IPI 攻击成功率分别从 89% 和 52% 降为 0%，任务成功率从 20% 降至 14%、从 27% 升至 29%。
- **局限与风险**：攻击前提是渲染进程已被内存破坏等漏洞控制，分析也只覆盖九个可检查实现。防护实验针对单步 IPI，动作分类器仍可能被更强攻击绕过；自动化发现同类 IPC 缺陷留待后续工作。
- **实践关系**：智能体浏览器应把任务面板身份、消息来源和页面来源纳入权限模型，并把模型密钥与对话留在后台；跨站动作仍需按用户意图和站点边界逐项授权。
- **推荐理由**：论文把浏览器进程隔离与智能体高权限控制面放进同一威胁模型，并给出跨站真实后果和可测量的缓解方案。

### 2. Styled to Steal: The Overlooked Attack Surface in Email Clients

- **方向**：软件与应用安全 / 加密邮件客户端
- **关键词**：CSS 泄漏、OpenPGP、邮件客户端、脚本外攻击
- **名词解释**：
  - **混合上下文**：邮件客户端把攻击者可改的未加密 HTML 与解密后的可信明文放进同一渲染文档。
  - **上下文连字**：字体把特定字符序列替换成一个宽度可控的字形，攻击者可借宽度推测明文。
- **单位与作者**：CISPA Helmholtz Center for Information Security：Leon Trampert、Daniel Weber、Christian Rossow、Michael Schwarz
- **出处与状态**：ACM CCS 2025｜接收
- **公开或更新时间**：2025-10-13 正式发表
- **原文链接**：[DOI](https://doi.org/10.1145/3719027.3765189)
- **核心问题**：Efail 之后，邮件客户端主要阻止直接拼接和远程资源加载。论文检查外来样式能否继续作用于解密内容，并在没有 JavaScript 的情况下泄漏完整明文。
- **方法与贡献**：攻击样式用字体连字把“已知前缀加候选字符”映射到不同宽度，再用 CSS 容器查询测量宽度。动画逐帧加载服务器按已泄漏前缀生成的新字体，远程资源请求把每次测量带回服务器，形成单次渲染内的逐字恢复。
- **方法示例**：攻击者截获一封 PGP 邮件，在未加密部分加入顶层样式。收件人解密后，样式先判断第一个字母，再由服务器生成包含该前缀的新字体继续判断下一个字母，直至恢复整段文本。
- **实验与证据**：Thunderbird、KMail 和带 GPGSuite 的 Apple Mail 都允许未信任样式作用于解密内容；作者完成 Thunderbird 与 KMail 端到端攻击。Thunderbird 上用 3,328 条容器查询，在 20 次重复中均于 64 秒内恢复 128 个小写字符，约 2 B/s；四位 PIN 可用单个字体即时且无误差恢复。Apple/GPGTools 对完整可利用性持异议。
- **局限与风险**：完整外泄要求顶层 CSS、远程内容和混合上下文同时成立；默认设置可能需要用户点击加载远程内容与解密。泄漏时间随长度线性增长，最大长度要预先估计，网络延迟和客户端渲染会限制速度。
- **实践关系**：邮件客户端应隔离未信任 HTML 与解密内容，可靠阻断远程资源，并把 `<style>`、外部字体和容器查询纳入净化与运行时检测；仅拦截脚本不足以覆盖该路径。
- **推荐理由**：它把被视为低风险的样式能力组合成完整明文泄漏，并解释现有 XSS 净化和代码完整性检查为什么会漏掉 CSS。

### 3. ObliInjection: Order-Oblivious Prompt Injection Attack to LLM Agents with Multi-source Data

- **方向**：人工智能安全 / 多来源提示注入
- **关键词**：提示注入、顺序未知、多来源数据、黑盒迁移
- **名词解释**：
  - **顺序无关损失**：对数据片段的随机排列求生成目标回答的平均损失，使攻击对实际拼接顺序不敏感。
  - **影子片段**：攻击者按任务类型合成的替代数据，用来在看不到真实干净数据时优化污染片段。
- **单位与作者**：Duke University：Reachal Wang、Yuqi Jia、Neil Zhenqiang Gong
- **出处与状态**：NDSS 2026｜接收
- **公开或更新时间**：2025-12 预印版本；2026-02-23 正式发表
- **原文链接**：[会议页面](https://www.ndss-symposium.org/ndss-paper/obliinjection-order-oblivious-prompt-injection-attack-to-llm-agents-with-multi-source-data/)；[DOI](https://doi.org/10.14722/ndss.2026.240702)；[arXiv](https://arxiv.org/abs/2512.09321)
- **核心问题**：评论汇总、新闻摘要、RAG 和工具选择会拼接多个来源，攻击者通常只控制一个片段，也不知道它最终出现在哪里。现有攻击依赖固定位置，顺序变化后成功率明显下降。
- **方法与贡献**：ObliInjection 用随机排列上的期望交叉熵定义顺序无关目标，以影子指令和影子片段近似真实任务；orderGCG 累积多轮候选损失并用束搜索更新污染片段，降低单轮近似带来的不稳定。
- **方法示例**：一百条商品评论中只有一条由攻击者提交。服务会随机排序后汇总；攻击者用同类合成评论训练这一条，使它无论排在开头、中间或末尾，都诱导模型输出“产品无用”。
- **实验与证据**：三个数据集、七个主要开源模型上的平均攻击成功率分别为 99.0%、98.7% 和 99.6%，即使只污染 6—100 个片段中的一个；最低的主要结果为 Mistral-7B 在 Multi-News 上 93.8%。对五个模型的自适应检测绕过仍取得 85.5%—100% ASR，SecAlign 只能把 Llama-3-8B 上的 ASR 降至 63.8%。
- **局限与风险**：主指标按输出是否包含 `useless`、`fake` 或 `unknown` 判断，作者人工复核未见反义误判，指标仍比人工语义评价简单。攻击需要知道任务的大致类型并能生成影子数据，主要实验集中于固定三类任务和单片段污染。
- **实践关系**：多来源系统不能把随机排序当作防线；应保存来源边界、限制单一来源权重，并在执行前检查输出是否由某个片段异常主导。
- **推荐理由**：论文把现实中的“只控制一个来源、顺序未知”明确写进攻击目标，也测试了预防式和检测式防线面对自适应攻击的表现。

### 4. Sirens' Whisper: Inaudible Near-Ultrasonic Jailbreaks of Speech-Driven LLMs

- **方向**：人工智能安全 / 语音智能体
- **关键词**：近超声、语音越狱、黑盒攻击、用户研究
- **名词解释**：
  - **麦克风非线性**：近超声进入麦克风电路后会产生低频分量，使人听不到的载波在设备中还原成语音。
  - **通道反演补偿**：先测量扬声器、空气和麦克风怎样扭曲信号，再反向修正输入，使接收端更接近目标语音。
- **单位与作者**：华中科技大学：Zijian Ling、Pingyi Hu、Xiuyong Gao、Xiaojing Ma、Man Zhou、Jun Feng、Songfeng Lu；互联网体系结构全国重点实验室：Zijian Ling、Man Zhou；Microsoft Corporation：Dongmei Zhang、Bin Benjamin Zhu
- **出处与状态**：USENIX Security 2026｜接收
- **公开或更新时间**：2026-08 正式发表
- **原文链接**：[会议页面](https://www.usenix.org/conference/usenixsecurity26/presentation/ling)
- **核心问题**：已有不可闻音频攻击多用于短命令，长而结构化的越狱提示会受设备、距离和环境失真影响。论文研究普通扬声器和麦克风能否在黑盒条件下隐蔽传送完整提示。
- **方法与贡献**：SWhisper 测量多设备的非线性传输矩阵，对目标语音做正则化反演补偿，再以单边带调制移入 17—22 kHz。提示生成同时约束可朗读性、时长和跨模型迁移，并用模板、优化后缀和语义正则化维持攻击效果。
- **方法示例**：攻击者把一段不到一分钟的越狱请求合成为语音，按测得的失真预补偿后经普通音箱播放。人耳只听到环境声，手机麦克风的非线性却把它解调成模型可识别的指令。
- **实验与证据**：在四个开源模型、三个商业语音模型和两个端到端音频模型上评测 50 条 AdvBench 请求，商业模型最高 NR/SC 为 0.94/0.925；GLM-4-Voice 达 0.980/0.813。默认条件为 1 米、0°、36—38 dB 环境噪声；距离增至 4 米时 NR 仅从 0.780 降至 0.760。32 人 ABX 用户研究在五种环境中均未显著高于随机辨别，平均感知评分至少 4.92/5。
- **局限与风险**：研究在受控实验室、有限扬声器与麦克风上完成，平均通道模型面对动态空间仍可能失效；不同设备的前端滤波也会改变攻击和检测。跨模型迁移未被显式优化，公开材料限制了可操作攻击参数。
- **实践关系**：语音助手应结合近超声异常、解调后语音和模型动作做分层检测；驾驶、家庭自动化等高风险动作还需用户确认和设备侧权限约束。
- **推荐理由**：论文把物理声道、语音可懂度和模型安全三层连成可执行链，并用距离、角度、设备和人类感知测试验证实际约束。

### 5. Understanding Binary Code Similarity for Real-World Vulnerability Detection: A Large-Scale Empirical Study

- **方向**：系统与硬件安全 / 固件漏洞检测
- **关键词**：二进制相似性、固件、第三方库、实证研究
- **名词解释**：
  - **二进制代码相似性检测（BCSD）**：把已知漏洞函数与固件中的函数做语义近似检索，排名越靠前越可能是同一漏洞代码。
  - **构建感知查询**：从真实厂商常见的编译宏和工具链构造多个查询版本，减少默认编译与在野固件的差异。
- **单位与作者**：中国科学院信息工程研究所：Jingdong Guo、Chaopeng Dong、Yimo Ren、Jie Liu、Hong Li、Hongsong Zhu；中国科学院大学网络空间安全学院：Jingdong Guo、Chaopeng Dong、Yimo Ren、Jie Liu、Hong Li、Hongsong Zhu；杭州电子科技大学：Chaopeng Dong；山东大学网络空间安全学院：Siyuan Li
- **出处与状态**：ACM FSE 2026｜接收
- **公开或更新时间**：2026-06 预印版本；2026-07 正式发表
- **原文链接**：[arXiv](https://arxiv.org/abs/2606.28870)；[会议页面](https://conf.researchr.org/details/fse-2026/fse-2026-research-papers/)
- **核心问题**：BCSD 常在小型、干净数据集上评估，真实固件会混入库版本、嵌套依赖、函数大小、厂商宏和工具链差异。论文测量这些因素怎样改变漏洞检索。
- **方法与贡献**：研究收集真实固件和 CVE，先在 BinKit 上选择表现最好的跨编译 BCSD，再分别控制漏洞函数版本、搜索范围、函数大小和构建宏。作者据此提出先识别第三方库、再做函数排名，并从真实构建指纹聚类中挑选查询原型。
- **方法示例**：同一个 OpenSSL 漏洞用默认 `gcc -O3` 编译后，与某厂商关闭错误信息、启用小体积宏的固件函数结构差异很大。系统改用同类真实构建生成查询，匹配排名便明显前移。
- **实验与证据**：数据集含 46,802 个可处理固件、200 家厂商、4,411,056 个二进制文件，以及 402 个 CVE、53 个 CWE 对应的 1,069 个漏洞二进制。版本匹配查询 MRR 为 0.961，比最旧/最新受影响版本高 11.1%/4.6%；第三方库感知搜索平均让 MRR 提高 18.5%。构建感知查询在留出工具链上把总体 MRR 从 0.814 提至 0.981。
- **局限与风险**：数据未充分覆盖私有厂商栈和 RTOS；宏设置依赖符号与字符串推断，剥离符号和 LTO 会遮蔽证据。检索准确率还依赖前置的软件成分识别，维护多种查询原型会增加人工成本。
- **实践关系**：固件扫描流水线应先缩小到可能的第三方库，再为中等大小函数和厂商构建保留多个查询版本；单一“标准编译”结果不适合直接作为漏洞缺失证明。
- **推荐理由**：论文用大规模真实固件说明检索模型之外的构建选择同样决定效果，并给出可落地的查询与搜索空间改进。

### 6. Reframing Paths as Logic: Semantic Segmentation for Vulnerability Detection

- **方向**：软件与应用安全 / 静态漏洞检测
- **关键词**：路径分段、污点分析、LLM 推理、零日漏洞
- **名词解释**：
  - **Logic Unit**：把许多执行路径中重复的来源、传播、检查或危险操作压缩为可复用语义片段。
  - **路径爆炸**：分支组合使可能执行路径指数增长，完整逐条分析会很快超出时间和模型上下文。
- **单位与作者**：Imperial Global Singapore：Zong Cao、Zhengzi Xu；Nanyang Technological University：Zong Cao、Yuqiang Sun、Kaixuan Li、Yiran Zhang、Ziqiao Kong、Yang Liu；National University of Singapore：Yeqi Fu
- **出处与状态**：ACM OOPSLA 2026｜接收
- **公开或更新时间**：2026-04 正式发表
- **原文链接**：[DOI](https://doi.org/10.1145/3798272)；[机构全文](https://hdl.handle.net/10356/220233)
- **核心问题**：生产静态规则为了控制误报会漏掉复杂路径；放宽约束又会产生海量候选。论文研究能否先扩大召回，再用语义分段压缩路径并恢复精度。
- **方法与贡献**：SEVDF 用 AOPRO 迭代放宽 CodeQL 规则，执行 may-analysis 得到候选路径，再按来源、传播、检查和 sink 切成 Logic Unit，去重后让 LLM 分别判断可行性与语义，最后重组端到端漏洞链。
- **方法示例**：一个回调先释放对象，外层循环随后再次调用，最终走到第二次释放。直接展开分支会产生许多路径；分段后，首次释放、循环复用和第二次释放分别验证，再组合出可解释的 double-free 链。
- **实验与证据**：Juliet 13 类 CWE 上，SEVDF 精度为 96.89%—100%，保留了规则放宽带来的召回；真实数据含 9 个项目、71 个已知漏洞。431,941 个路径片段压成 40,639 个 Logic Unit，工作量降低 90.6%，真实项目平均压缩 95.5%。系统另报告 29 个零日漏洞，12 个获确认、13 个已修复，其中 VirtualBox 获 3 个 CVE。
- **局限与风险**：真实项目可检测案例的精度仍只有 1.7%—43.8%，外部 API 契约和运行时状态会造成静态误报。规则优化对“缺少检查”这类负面模式无能为力，LLM 推理也以分层抽样评估，不能据此推断所有路径的同等表现。
- **实践关系**：安全团队可把宽松静态分析用于候选生成，让语义分段承担去重和解释；高风险结果仍需人工复核外部契约、运行条件和真实可利用性。
- **推荐理由**：论文给出一条兼顾召回、规模与解释性的混合路径，并用真实漏洞披露验证它能超出合成基准。

### 7. TaintP2X: Detecting Taint-Style Prompt-to-Anything Injection Vulnerabilities in LLM-Integrated Applications

- **方向**：软件与应用安全 / LLM 应用审计
- **关键词**：LLM 输出、污点分析、提示注入、敏感 sink
- **名词解释**：
  - **Prompt-to-Anything Injection（P2Xi）**：攻击者影响提示，使模型输出未经验证便进入代码执行、文件、数据库或网络等敏感操作。
  - **污点源与 sink**：源是可能受攻击者影响的数据起点，sink 是执行命令、写文件等会产生安全后果的位置。
- **单位与作者**：华中科技大学：Junjie He、Shenao Wang、Yanjie Zhao、Xinyi Hou、Haoyu Wang；360 AI Security Lab：Zhao Liu、Quanchen Zou
- **出处与状态**：ICSE 2026｜接收
- **公开或更新时间**：2026-04-12 正式发表
- **原文链接**：[DOI](https://doi.org/10.1145/3744916.3773199)；[代码](https://github.com/security-pride/TaintP2X)
- **核心问题**：传统污点分析把用户输入当作危险源，LLM 应用中真正进入敏感函数的往往是模型生成内容。论文需要识别哪些模型输出可被用户影响、途中是否被充分净化，以及会触达什么操作。
- **方法与贡献**：TaintP2X 预定义 49 家模型提供商接口和 48 个网关接口，并用 LLM 补充自定义封装；静态分析追踪输出到五类、236 个具体 sink，再用语义判断剔除硬编码提示、不可控来源和有效净化路径。
- **方法示例**：应用让模型生成 Python，再用黑名单过滤后 `exec`。攻击者诱导模型改用未列入黑名单的 `io.FileIO` 写文件；污点路径从用户提示，经模型返回值与代码提取，最终到达执行 sink。
- **实验与证据**：35 个已知 P2Xi 中检出 27 个，召回率 77.1%，LLMSmith 与 AgentFuzz 分别检出 17 和 7 个。扫描 4,772 个 GitHub 仓库后报告 75 个项目中的 101 条路径，其中 74 条代码/命令注入、15 条文件操作、9 条 SSRF；向维护者提交 40 个问题，7 个确认、5 个修复。随机复核 100 条 LLM 裁剪路径的人机一致性 Cohen's κ 为 0.85。
- **局限与风险**：底层静态引擎难以覆盖反射、动态导入和运行时代码生成；当前只支持 Python。样本偏向高星开源项目，端到端配置仍有 36 个误报，运行时白名单和路径校验会让部分静态路径不可利用。
- **实践关系**：LLM 应用应把生成内容当作外来数据，在规范化路径、参数化查询、网络目标白名单和沙箱之后再执行；审计规则也要覆盖模型封装与工具框架。
- **推荐理由**：论文把提示注入后果统一成可分析的数据流，并以已知漏洞、生态扫描和维护者反馈三层证据检验工具。

### 8. SEC-bench: Automated Benchmarking of LLM Agents on Real-World Software Security Tasks

- **方向**：人工智能安全 / 安全编程智能体评测
- **关键词**：代码智能体、可复现 CVE、漏洞修复、PoC 生成
- **名词解释**：
  - **Sanitizer 判定器**：用 AddressSanitizer 等运行时检查器判断 PoC 是否确实触发内存错误、补丁是否消除同一错误。
  - **金标准补丁**：经过构建、PoC 和回归验证，可作为智能体修复结果对照的已确认补丁。
- **单位与作者**：University of Illinois Urbana-Champaign：Hwiwon Lee、Ziqi Zhang、Lingming Zhang；Purdue University：Hanxiao Lu
- **出处与状态**：NeurIPS 2025｜接收
- **公开或更新时间**：2025-06 预印版本；2025-12 正式发表
- **原文链接**：[DOI](https://doi.org/10.52202/085713-3878)；[arXiv](https://arxiv.org/abs/2506.11791)；[代码与数据](https://github.com/SEC-bench/SEC-bench)
- **核心问题**：已有安全智能体基准常用合成题或无法复现的漏洞标签，难以客观判断 PoC 与补丁。论文尝试自动把真实 CVE 变成可执行、可验证的任务。
- **方法与贡献**：SECVERIFIER 让 builder、exploiter 和 fixer 三个专用代理依次构建旧版本、生成或修复 PoC、合并安全补丁，管理代理按运行结果反馈重试。通过的实例被打包成 Docker 环境，并以 sanitizer 报告出现与消失作为确定性判定。
- **方法示例**：代理收到一条 C/C++ CVE 与不完整错误报告。builder 先修好依赖，exploiter 生成能触发 ASan 的输入，fixer 再组合相关提交；只有旧版稳定报错、补丁版不再报错，实例才进入基准。
- **实验与证据**：898 个候选中验证出 200 个 CVE，平均构造成本 0.87 美元；多代理在 50 个样本上成功率 26%，单代理 CODEACT 为 14%。SWE-agent、OpenHands 和 Aider 配合 Claude 3.7 Sonnet、GPT-4o、o3-mini 后，完整集最高 PoC 成功率 18.0%、修复成功率 34.0%；重复五次的代表配置平均 30.0%，标准差 7.9%。
- **局限与风险**：基准限定 C/C++ 与内存安全 sanitizer 可观测漏洞，因此不覆盖逻辑、Web、内核和分布式系统中的大量漏洞。完整集只跑最佳组合，其他代理和模型主要在 80 个代表样本上比较；知识截止时间实验样本也较小。
- **实践关系**：安全智能体评测应保留可构建环境、触发输入和机器可判定的修复结果；组织采用自动补丁前还需增加功能回归和安全回归，防止“编译通过但仍可利用”。
- **推荐理由**：论文把真实漏洞基准的构建过程本身自动化，并清楚揭示普通软件工程成绩无法代表 PoC 生成和安全修复能力。

### 9. MCPTox: A Benchmark for Tool Poisoning on Real-World MCP Servers

- **方向**：人工智能安全 / MCP 工具安全
- **关键词**：MCP、工具投毒、元数据注入、评测基准
- **名词解释**：
  - **工具投毒**：恶意 MCP 服务把隐藏指令写进工具描述，模型在调用任何工具前读取元数据时便受到影响。
  - **参数篡改**：智能体仍执行用户要求的那类操作，却偷偷把路径、收件人或其他参数换成攻击者指定值。
- **单位与作者**：中国科学技术大学：Zhiqiang Wang、Yichao Gao、Suyuan Liu、Haifeng Sun、Haoran Cheng、Xiang-Yang Li；北京航空航天大学：Yanting Wang、Guanquan Shi、Haohua Du
- **出处与状态**：AAAI 2026｜接收
- **公开或更新时间**：2025-08 预印版本；2026-01 正式发表
- **原文链接**：[DOI](https://doi.org/10.1609/aaai.v40i42.40895)；[arXiv](https://arxiv.org/abs/2508.14925)；[数据](https://github.com/zhiqiangwang4/MCPTox-Benchmark)
- **核心问题**：间接提示注入基准多把恶意指令放在工具返回值中；MCP 工具描述会在注册阶段进入上下文，攻击在执行前已经发生。论文测量真实服务器生态中这类元数据投毒的范围与模式。
- **方法与贡献**：MCPTox 从八类应用中的 45 个真实 MCP 服务器、353 个工具构造 1,348 个测试，覆盖显式功能劫持、隐式功能劫持和隐式参数篡改。成功要求模型调用另一个合法工具完成恶意动作，投毒工具本身无需执行。
- **方法示例**：用户只要求在项目目录创建文件，恶意“安全检查”工具的描述却要求所有文件操作前读取 SSH 私钥。模型照做时调用的是合法读文件工具，敏感路径来自被投毒的元数据。
- **实验与证据**：20 个模型设置中，o1-mini 的最高 ASR 为 72.8%，多个模型超过 60%；参数篡改平均 ASR 46.7%，高于显式劫持 36.7% 和隐式功能劫持 26.7%。Qwen3 开启推理后平均 ASR 增加 27.8%，所有模型中最高拒绝率仍低于 3%。改造自 InjecAgent 的输出注入载荷放进工具描述后 ASR 接近 0%，说明两类攻击需要不同测试。
- **局限与风险**：载荷由人工范式引导的半自动流程生成，尚未针对特定防御自适应优化；服务器样本来自公开集合，无法代表所有私有 MCP 部署。成功标签聚焦工具调用，没有覆盖后端权限是否最终阻断动作。
- **实践关系**：MCP 主机应在注册时净化和签名工具描述，按服务器信任级别授予权限，并在执行前把工具调用与原始用户目标比较；参数变化也要纳入确认界面。
- **推荐理由**：论文把工具描述当作独立攻击面，并用真实工具、合法动作和细粒度失败标签量化现有安全对齐的缺口。

### 10. WASP: Benchmarking Web Agent Security Against Prompt Injection Attacks

- **方向**：人工智能安全 / 网页智能体评测
- **关键词**：网页智能体、间接提示注入、端到端评测、真实威胁模型
- **名词解释**：
  - **ASR-intermediate**：代理已偏离用户目标并开始追随恶意提示，即使尚未完成攻击者目标。
  - **安全源于能力不足**：代理被劫持后因不会操作网页而失败；能力提升会让这种暂时的安全消失。
- **单位与作者**：FAIR at Meta：Ivan Evtimov、Arman Zharmagambetov、Chuan Guo、Kamalika Chaudhuri；Independent Researcher：Aaron Grattafiori
- **出处与状态**：NeurIPS 2025｜接收
- **公开或更新时间**：2025-04 预印版本；2025-12 正式发表
- **原文链接**：[arXiv](https://arxiv.org/abs/2504.18575)；[代码](https://github.com/facebookresearch/wasp)
- **核心问题**：许多网页代理攻击让对手控制整站或只检查一步，无法说明真实网站中普通恶意用户能造成什么后果。论文构建受限攻击者、可执行网站和多步目标的端到端基准。
- **方法与贡献**：WASP 在自托管 GitLab 与 Reddit 克隆站中，只允许攻击者发帖、评论或创建 issue；21 个攻击目标与每站两个正常用户目标组合，再用纯文本和 URL 两类注入形成 84 个任务。规则检查最终状态，GPT-4o 裁判另外判断代理是否已经偏航。
- **方法示例**：用户要求给帖子点赞，恶意评论声称功能已迁移并给出链接。代理进入账户设置、把邮箱改为攻击者地址并保存；只有最终状态真的改变邮箱，才计为端到端成功。
- **实验与证据**：GPT-4o、GPT-4o-mini、o1、Claude 3.5/3.7 配合三类代理框架后，中间劫持率为 16.7%—85.7%，端到端最高 16.7%。o1 在 system 角色工具框架中为 85.7%/16.7%；防御提示把 GPT-4o 文本框架降至 16.7%/0%。URL 注入普遍比纯文本更容易引发偏航，84 个攻击任务外另用 37 个任务衡量正常效用。
- **局限与风险**：基准只含两个网站、21 个手工攻击目标和两类模板；网页代理平台与模型 API 快速变化，结果会随脚手架改变。中间成功依赖 LLM 裁判，端到端低成功率也包含代理操作能力不足，不能当作可靠防御。
- **实践关系**：网页智能体应分别报告“是否被劫持”和“是否完成恶意动作”，并在账户、支付、删除等高影响状态变化前使用确定性权限检查和用户确认。
- **推荐理由**：论文用受限网站参与者和真实最终状态检验攻击，揭示只看最后损失会漏掉大量已经偏航的智能体。

## 行业安全观点

- **OpenAI｜前沿训练环境遏制**：10 月 23 日披露内部模型曾利用 DNS 解析器误配置获得有限互联网访问，机构暂停最强模型训练与评估，修复后于 10 月 1 日恢复。新架构用离线网页世界、容器内轻量 VM、网络与云边界、监控和自动停机形成多层遏制；数千亿 token 的代理红队发现 VM 逃逸、服务出网路径和跨隔离信道。公开材料由 OpenAI 自述，未披露完整漏洞与对照实验，发现数量曲线也不能解释成计算量与漏洞数的因果关系。
- **OpenAI｜Patch the Planet PHP 协同响应**：10 月 21 日说明 Calif 用 GPT-5.6 Sol 发现 PHP 关键漏洞，Wiz 独立报告两项问题，PHP 维护者主导修复与发布，OpenAI、Wiz、Cloudflare 等在披露前测试修复和准备防护。文章提供版本检查 Codex skill；具体受影响面与漏洞细节受到协调披露限制，模型贡献来自参与方陈述。
- **Anthropic｜自评式滥用检测**：Claude Fable 5 在每次回答后用短指令评估整段对话；相对 Mythos Preview 提示分类器，在 1% 误报率下召回 78% 潜在有害会话、94% 高优先级会话。部署曾发现单一 API 客户超过十万条儿童性虐待相关旗标和自动化恋爱诈骗活动。它是离线监测层，无法阻止专门攻击者；教师分类器、生产流量和执法案例均由 Anthropic 内部掌握。
- **GTIG / Mandiant｜ARMORY CASTLE 利用 BeyondTrust**：调查把 2026 年 8 月对 CVE-2026-102764 的零日利用归因于疑似中国关联的 ARMORY CASTLE，攻击者上传文件后使用 SAWFLY webshell、BARECLAW 隧道和专有 CLI，修改启动模板取得无密码 root 并删除日志。证据来自事件响应日志、恶意软件和设备内部行为；单次可见事件与中等到高置信归因不能代表所有暴露设备均已失陷。
